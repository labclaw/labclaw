### P1-01: CUA scroll/drag/move映射产生无效action shape

- **子项目**: device-use
- **文件**: `src/device_use/backends/openai_compat.py:421-429`
- **发现方式**: Codex运行`parse_action()`得到`ValidationError`和`ValueError`
- **问题描述**:
  - `scroll` action缺少必需字段`clicks`，`parse_action()`抛`ValidationError`
  - `drag` action缺少`start_x/start_y/end_x/end_y`，只产生无效的`coordinates: [None, None]`
  - `move` 不是合法`ActionType`枚举值，`parse_action()`抛`ValueError`
- **影响**: GPT-5.4发出scroll/drag/move时agent直接崩溃，3次连续错误后停止
- **修复方案**:
  ```python
  # scroll: 添加clicks字段，映射scroll_x/scroll_y到dx/dy
  if action_type == "scroll":
      return {"action": {"action_type": "scroll", "coordinates": [x, y],
              "clicks": cu.get("scroll_y", -3) // -120 or -3,
              "dx": cu.get("scroll_x", 0), "dy": cu.get("scroll_y", 0)}}

  # drag: 从path提取start/end坐标
  if action_type == "drag":
      path = cu.get("path", [])
      start = path[0] if path else {"x": 0, "y": 0}
      end = path[-1] if path else {"x": 0, "y": 0}
      return {"action": {"action_type": "drag",
              "start_x": start["x"], "start_y": start["y"],
              "end_x": end["x"], "end_y": end["y"]}}

  # move: 映射为click但不按下（或添加move到ActionType）
  if action_type == "move":
      return {"action": {"action_type": "click", "coordinates": [x, y],
              "button": "none"}}  # 或添加move支持
  ```
- **验证方法**:
  ```bash
  cd device-use
  PYTHONPATH=src .venv/bin/python -c '
  from device_use.backends.openai_compat import OpenAICompatBackend
  from device_use.actions.models import parse_action

      {"action_type": "scroll", "x": 10, "y": 20, "scroll_x": 0, "scroll_y": -120},
      {"action_type": "drag", "path": [{"x": 1, "y": 2}, {"x": 3, "y": 4}]},
      {"action_type": "move", "x": 10, "y": 20},
  ]
  for cu in tests:
      mapped = OpenAICompatBackend._map_cu_action(cu)["action"]
      act = parse_action(mapped)
      print(f"OK: {cu['action_type']} → {type(act).__name__}")
  '
  ```
  - 期望: 3个OK，无异常
  - 运行测试: `PYTHONPATH=src .venv/bin/python -m pytest tests/test_backends.py -v`

### P1-02: pending_safety_checks永远不会被检测到

- **子项目**: device-use
- **文件**: `src/device_use/backends/openai_compat.py:132-138`
- **发现方式**: Codex通过`ResponseComputerToolCall.model_fields`确认`pending_safety_checks`是`computer_call` item的字段
- **问题描述**:
  当前代码检查`getattr(item, "type", None) == "pending_safety_checks"`，但SDK中`pending_safety_checks`是`computer_call`类型item上的一个**列表字段**，不是独立的output item类型。
- **影响**: GPT-5.4标记需要安全确认的操作时，device-use会直接执行而不是暂停。**安全机制被绕过。**
- **修复方案**:
  ```python
  # 替换当前的检查逻辑
  # 旧:
  for item in getattr(response, "output", []):
      if getattr(item, "type", None) == "pending_safety_checks":
          logger.warning(...)

  # 新:
  for item in getattr(response, "output", []):
      if getattr(item, "type", None) == "computer_call":
          checks = getattr(item, "pending_safety_checks", [])
          if checks:
              logger.warning("CU response has pending safety checks: %s", checks)
              raise RuntimeError(
                  f"GPT-5.4 requires safety acknowledgement: {checks}. "
                  "Refusing to execute unacknowledged actions."
              )
  ```
- **验证方法**:

  ```python
  history_entry = {
  ```

### P1-05: 批量actions只执行第一个

- **子项目**: device-use
- **文件**: `src/device_use/backends/openai_compat.py:383-389`
- **发现方式**: Codex逻辑追踪
- **问题描述**:
  Responses API的`computer_call`可返回`actions[]`批量动作，`_plan_native()`只暴露第一个mapped action，其余存入`_remaining_actions`。但`DeviceAgent.execute()`只读`plan["action"]`，忽略`_remaining_actions`。
- **影响**: 如GPT-5.4返回"先点击菜单再点击选项"的批量操作，只执行第一步
- **修复方案（二选一）**:
  - 方案A: `DeviceAgent`执行完`plan["action"]`后检查并执行`_remaining_actions`
  - 方案B: `_plan_native()`将所有actions合并为一个复合action序列
  - **推荐方案A**——保持action粒度，每个action独立通过安全检查
  ```python
  # agent.py execute循环中，执行完主action后:
  remaining = plan.get("_remaining_actions", [])
  for extra_action in remaining:
      # 每个额外action也通过安全检查
      safety_result = self._safety.check(extra_action)
      if safety_result.allowed:
          self._executor.execute(extra_action)
          time.sleep(0.12)  # 120ms inter-action delay (OpenAI CUA pattern)
  ```
- **验证方法**:

### P2-04: EventRegistry和EventBus双通道分裂

- **子项目**: labclaw
- **文件**: `src/labclaw/core/events.py` + `src/labclaw/core/event_bus.py`
- **发现方式**: Claude深度代码审查
- **问题描述**:
  `EventRegistry.emit()`和`EventBus.publish()`各自维护独立的handler字典。步骤代码用`event_registry.emit()`直接发布，但如果某个组件通过`event_bus.subscribe()`注册了handler，该handler收不到事件。反之亦然。
- **影响**: 静默事件丢失——取决于消费者用哪个API注册
- **修复方案（二选一）**:
  - 方案A: `EventBus.publish()`委托给`EventRegistry.emit()`，统一分发路径
  - 方案B: 废弃`EventRegistry.emit()`，所有发布走`EventBus`
  - **推荐方案A**——改动最小
  ```python
  # event_bus.py:
  class EventBus:
      def publish(self, event_name: str, data: Any = None):
          # 委托给registry，确保所有handler都收到
          self._registry.emit(event_name, data)
          # 然后触发bus自己的额外handler（如果有）
          for handler in self._handlers.get(event_name, []):
              handler(data)
  ```
- **验证方法**:
  ```bash
  cd labclaw
  python -c '
  from labclaw.core.events import event_registry
  from labclaw.core.event_bus import EventBus

  received = []
  bus = EventBus()
  # 通过bus订阅
  bus.subscribe("test.event", lambda data: received.append(("bus", data)))
  # 通过registry发布
  event_registry.register("test.event", "Test event")
  event_registry.emit("test.event", {"msg": "hello"})
  # 验证bus的handler也收到了
  assert len(received) > 0, "bus handler应该收到registry的事件"
  print("OK: 事件统一分发")
  '
  ```
- **工作量**: ~40行
- **分配给**: `_____`

### P2-07: device-skills无BaseDriver ABC

- **子项目**: device-skills
- **文件**: `src/device_skills/base.py`
- **发现方式**: Claude深度审查
- **问题描述**: `TopSpinDriver`和`Gen5Driver`通过鸭子类型实现labclaw的driver协议，无共享ABC。接口不一致在运行时才暴露。
- **影响**: labclaw `HardwareManager`调用driver时，类型错误在运行时而非定义时暴露
- **修复方案**:
  ```python
  # base.py新增:
  from abc import ABC, abstractmethod

  class BaseDriver(ABC):
      """异步设备驱动基类——labclaw HardwareManager的契约。"""

      @abstractmethod
      async def connect(self, config: dict[str, Any]) -> bool: ...

      @abstractmethod
      async def disconnect(self) -> None: ...

      @abstractmethod
      async def read(self, query: dict[str, Any]) -> dict[str, Any]: ...

      @abstractmethod
      async def write(self, command: dict[str, Any]) -> bool: ...

      @abstractmethod
      def info(self) -> dict[str, Any]: ...
  ```
  然后让`TopSpinDriver(BaseDriver)`和`Gen5Driver(BaseDriver)`继承。
- **验证方法**:
